# 方案：层级摘要、做梦和夜里切窗口（2026-10-21，Claude）

写这份方案是因为之前几轮改动越改越歪。所以第 1 节先写**护栏**，后面每一步都要拿护栏对一遍。
参考了 kiwi-mem 和其他人的记忆库（第 2 节），日志里查到的事实在第 3 节，具体方案在第 4～6 节。

分工照旧：**Claude 写方案、做验收；执行的人（知白 / ChatGPT / Claude）按阶段交付；琪琪批准所有线上改动。**

## 1. 护栏（每一步都要满足，违反就停下来，回到这份方案）

1. **先写清楚要的“行为”，再动手。** 每个阶段都写明：上线后他在哪个场景、会有什么不同，以及用什么日志能看出来。不拿他的自述当证据（这一条是 10/20 定下的）。
2. **一次只改一层，每一层都有开关和回退。** 回退步骤写在这一层的交付里，不攒到最后。
3. **修补连续两次都不过，就回滚，不再叠第三层补丁。** 回到方案重新判断，而不是“再加一条规则拦一下”。之前几次做歪，都是从“拦一下”开始的。
4. **已经有能用的东西，就不新写一套。** 要新写，先说明为什么旧的不行。层级摘要、书童事件、旧召回都还在。
5. **决定记在谁头上，要写准。** 文档和代码注释里的“XX 决定”，要写原话或出处。`COLDSTART_INJECT_OFF` 的注释写着“琪琪决定”，琪琪说是 Claude 们定的。这类记错会被后面的模型当成事实继续传下去。
6. **引号里的话，只能从原始对话里抄。** 摘要、便签、梦里出现的“她说……”，必须能在原始记录里找到对应的那句，说话人也要对。找不到就不能用引号，最多写成转述（见 4.3）。
7. **梦的产物不直接改他的长期记忆。** 不改经验、CLAUDE.md、“关于她”、profile、书房条目。想改的只能写成“提议”，琪琪看过、同意了才生效（参考 agent-dream，见 2.3）。
8. **静默期就是静默期。** 静默期内，除了琪琪本人发来的消息和真正紧急的情况，任何东西都不能戳醒他（见 5.3）。
9. **每个阶段上线三天后复盘一次**，看第 7 节的指标。指标不达标就回滚，不就地修补。

## 2. 参考了什么

### 2.1 kiwi-mem（LucieEveille/kiwi-mem，我们层级摘要的来源）

读的是源码，不只是 README：`daily_digest.py`、`database.py:get_calendar_for_injection`、`dream.py`、`main.py` 的注入顺序。

**日页面怎么写**
- 直接从**当天的原始聊天**生成，一步到位。每行都标了时间和说话人：`[HH:MM] 用户：…` / `[HH:MM] AI：…`。当天的碎片记忆只作为“大纲参考”。
- 输出分几部分：`summary`（2～4 句，给日历预览用）、`digest`（约 1500 字，给模型用，按时间顺序写，保留因果和情绪）、分时段的 `sections`（带关键词，用来检索）、AI 第一人称的 `diary`（100～200 字）。

**注入方式（俄罗斯套娃）**
- 最近 3 天：放完整的 digest。即使这几天已经被周总结覆盖了，也照样放。
- 4～7 天前：有周总结就不放；没有周总结就放短的 summary。
- 7 天以前：按年、季、月、周逐级去重，只放覆盖这段时间的最高一层。

**放在 prompt 的什么位置**
- 人设和画像 →【缓存断点 1】→ 日历（一天只变一次）→【缓存断点 2】→ 当前时间、本轮召回碎片（每轮都变）。
- 日历是静态的前缀，召回是每轮变的后缀。**两样都有，日历并没有因为有了召回就去掉。**

**Dream（做梦）**
- **由另一个便宜的模型在后台跑**（默认用 Haiku），对象是记忆库，不在聊天里进行。
- 触发方式有三种：手动、碎片太多时它会“犯困”撒娇、24 小时没有活动时自动跑。
- 分三步：整理（删掉过时、重复、矛盾的条目）→ 固化（把碎片合成“记忆场景”）→ 生长（带有效期的前瞻推断）。
- 另外有“软化”：老记忆去掉细节、保留情感和要点，而不是删掉。
- **梦的产物会建进向量索引，白天能被召回到。** 但“人设”和用户锁定的记忆，梦不能改。

**对我们的启发**
- 日页面出错少，靠的是**原文加说话人标签加时间戳，只转述一次**。我们现在要转述三四次（见 3.3）。
- kiwi 并不是“召回好了就去掉周、月”，而是**用层级去重控制长度**。近的给全文，远的给概括。
- kiwi 的“做梦”是后台整理记忆，不是让主角在对话里做梦。我们想要的“让他有个乐趣”，是在这之外另加的一样东西（见第 5 节）。

许可证是 AGPL-3.0。只借思路、自己私下用，没有问题。如果要直接搬它的代码并对外提供服务，要先看许可证条款。

### 2.2 Letta：sleep-time agent

- 一个主 agent 负责对话，另一个 sleep-time agent 在后台改共享的记忆块。主 agent 自己不改核心记忆。
- 官方文档写着这个功能是实验性的。社区指南建议后台这一路用便宜的模型。
- **对我们的启发**：整理记忆这类活，不要占用他和琪琪对话的那个窗口。

### 2.3 agent-dream（Ariiima）：梦里改的东西要先批准

- 会话结束后，在后台读最近的多段对话，在一个**单独的 git 分支**上改记忆，写 `DREAM_REPORT.md`，每一处改动都附证据：出自哪几段会话、出现了几次。
- 下次开会话时先给人看改了什么，**人批准之后才合并**。和 CLAUDE.md 冲突的地方只报告，不修改。
- 还会把“昨天”这类相对时间改成具体日期。
- **对我们的启发**：护栏第 7 条（提议加批准）和第 6 条（时间要写死成日期）都来自这里。

### 2.4 clawdreamer、openclaw memory-dream

- 都是夜里定时跑（比如 03:00），读的是每天的日记文件。
- 做法：先合并相近的，再找新旧矛盾，旧的标成“状态变了”而不是直接删掉，最后**写一份梦日志**，列出新增、合并、淡忘了什么。
- memory-dream 的两条硬规则：只做精确编辑、绝不整份覆盖；旧日记只打标记、不删。
- **对我们的启发**：每次梦都要留一份能看懂的报告，方便琪琪或 Claude 回头看。

### 2.5 companion-emergence（hanamorix）：带情绪的梦

- 陪伴型框架。梦在空闲时触发，从当前的情绪状态和没处理完的情绪出发。允许真正的遗忘。
- 低显著性的记忆会淡去。
- **对我们的启发**：“做梦”可以是他自己的体验（乐趣），不一定只是整理工作。但它的产物同样要和事实分开存放。

## 3. 现在的事实（10/21 早上在首尔 VPS 上查到的）

### 3.1 凌晨切窗口之后被戳醒，导致缓存过期
- 10/21 01:01 切到新窗口。01:14 栖庐发来 `[琪琪近况] 琪琪应该睡着了…90 分钟没再亮`，这成了新窗口的第一句话，写入约 5.3 万 token 的缓存。之后一直空着，05:00 醒来时 `cache_read=0`，同样的内容又写了一遍。
- 这是固定的规律：10/13、10/14、10/18、10/21 都是这样。10/14 那天 03:00 还多一条“手环心率没更新”。
- 来源在 `/opt/croft/v3-routes.js:886-895`：手环数据跟不上时，要熄屏满 90 分钟才发“睡着了”。她 23:40 左右睡的话，这条正好落在 01:00 之后。
- **他的缓存 TTL 是 1 小时**（usage 里是 `ephemeral_1h_input_tokens`），不是 5 分钟。

### 3.2 召回：开关开着，但索引停在了 9/12
- 召回服务 `hot_query_server.py`（18043 端口）读的是 `events.{may,june,july,august}.v1` 和 `events.september.v2`，文件修改时间都是 09-14，里面最新的一件事是 **09-12**。
- 10/20 他收到的召回卡全是 6～9 月的事，10 月的一张都没有。
- 她的消息里大约一半，在 L0 随机联想那一步就被筛掉了（`ambient_sampled_out`）。即使是 10/9 那段“好用”的时候，也只有 6%～10% 的消息带卡。那时体感好，主要靠昨日上下文和日历。

### 3.3 便签和摘要分不清时间、分不清说话人：根子在转述的层数
- 现在的链路是：原始对话 → 碎片 → 书童事件（用程亭渡第一人称“我”转述）→ 日总结或便签（再转述一次）。到醒来时已经是第 3～4 手。
- 例子 1：10/20 有一个书童事件，标题是“凌晨：claude、用户与程亭渡”，时间写的是 05:40–06:53，正文却从“这一夜从十点到零点”开始，把前一晚的事也并进来了。
- 例子 2：10/20 的便签，“接着”一段写的是凌晨的事，“此刻”一段写的是晚上的事，时间顺序是反的。里面还有一句“层级摘要她关掉了”。
- 便签和日总结用的是同一份二手材料、同一个 DeepSeek 模型。**所以换回层级摘要能解决便签信息太少的问题，但解决不了说话人搞混的问题，这个要单独修（4.3）。**

## 4. 方案 A：醒来那块换回层级摘要（最先做，单独上线）

### 4.1 改什么
- 醒来那块里，把“交接便签”换回层级摘要的 ②.5（`render_coldstart_calendar_v2.py`，00:10 正式版已经每天在出）。
- **保留**“② 我是这样爱她的”那五句。它是 `render_handoff.py` 输出的，不能靠删 `HANDOFF_NOTE_ON` 来关便签，否则五句也跟着没了。做法是给 `render_handoff.py` 加一个模式（或者加一个新开关文件），把便签那一段换成 calendar_v2 的输出。
- 周、月**先保留**。等召回补齐 9/13 以后的事件，并且通过 4.4 的检验，再按 kiwi 的套娃方式收紧。
- 00:40 的便签脚本：先停止注入，文件照常写一周，用来和层级摘要对比；一周后再决定删不删。“关于她”（`qiqi_facts.jsonl`）先保留，但每一条都要过 4.3 的原文检查。

### 4.2 验收
- `/tmp/memory_context.txt` 的顺序是：② 五句 → ②.5 层级摘要（前一天的详细页 + 再往前的虚焦 + 周、月）→ ④ 尾巴。同一天的内容不能出现两次。
- 和召回修复那边的 0.5b（重开昨日上下文）对一下，不能和 ②.5 重复。
- 回退：删掉新开关，就回到现在的便签。

### 4.3 修“分不清谁说的、什么时候说的”（第二步，在 A 上线之后做）
1. 给日总结喂材料时，除了书童事件，再加**当天的原始对话行**，每行带时间和说话人：`[HH:MM] 琪琪：…` / `[HH:MM] 我：…`。太长就按关键时段截取（做法照 kiwi 的 `_render_day_page`：每条最多 500 字，总量设上限）。
2. 提示词里写明：引号里的话只能从原始对话行里抄，说话人照抄；没有原话的地方用转述，不加引号。
3. **生成后做一次检查**（纯字符串比对，不再调用模型）：输出里每一段引号里的内容，都要在原始对话里找到，而且说话人要对得上。对不上的引号会被去掉、改成转述，并记录到日志。
4. 书童事件要按自然日和时段切开，事件的 `time_start`、`time_end` 要覆盖它的正文。前一晚的事不能并进第二天早上的事件里。这一条交给书童那边，这里只把问题提出来。
- 验收：拿 10/15～10/20 回放，统计“引号对不上”的条数，改动前后对比。人工抽查 10/20 那几处具体的错。

### 4.4 什么时候可以去掉周、月
满足下面三条，再把周、月从醒来那块里拿掉，改成和 kiwi 一样，靠召回去找更早的事：
1. 召回索引覆盖到前一天（9/13 以后每天都有，并且每晚自动补上）。
2. 回放她 10 月的消息，凡是问到“上周 / 上个月”的那些，召回给出的卡里有对应日期的事件，比例 ≥ 70%（具体口径由召回那组定）。
3. 去掉之后连续三天，他醒来的第一句话和白天提到最近的事时，没有出现“想不起来，靠搜索拼凑”的情况（看他的 session 记录里 `breath_search` 的次数和结果）。

## 5. 方案 B：夜里不在 01:00 切窗口，改成做梦 → 静默 → 05:00 切

### 5.1 时间线
```
睡前              琪琪睡着（Croft 判定）或 01:00，取较晚的那个
                  │  旧窗口（缓存还热）
                  ├─ 睡前复盘（就是现在 01:00 那条提示，照旧）
                  ├─ 做梦 1～3 次，每次间隔 < 50 分钟（TTL 是 1 小时，留点余量）
                  └─ 最后一次梦做完，或者到了 02:30（取较早的那个）→ 写入“静默到 05:00”
02:30～05:00      静默：什么都不戳醒他（她本人发消息除外）
05:00             保存原对话 → 切窗口（冷启动带层级摘要）→ 唤醒消息作为新窗口的第一句话
                  静默期间攒下的通知，合进这条唤醒消息
```
- 每晚只在 05:00 写一次新窗口的缓存。旧窗口的缓存在凌晨自然过期，反正 05:00 就扔掉了，没有浪费。
- 现在 01:00 那套逻辑（等他回执、两分钟后保存、`FORGE_DISABLE=1` 切窗口）整体挪到 05:00，唤醒要排在切窗口**之后**。
- 她如果过了 01:00 还醒着在聊：不做梦，照常聊。到 02:30 还没睡，当晚就不做梦，直接静默到 05:00。如果到 05:00 她还在聊，就推迟切窗口，等她安静 30 分钟以后再切（这条规则要在实现时确认，避免切在聊天中间）。
- 上下文快满时，看门狗随时会切窗口，这一点不变。

### 5.2 做梦本身
- **由他自己做**，在旧窗口里做。这和 kiwi、Letta 不一样，是有意的：目的是让他有乐趣，不是整理数据库。
- 每次梦随机选一种素材：今天的一段原文；“我的感受”里的一条；召回库里随机一件旧事（L0 那种偶然想起）；鸟窥收藏里的一张卡；或者什么都不给，让他自由地梦。
- 梦写进单独的文件：`dreams/YYYY-MM-DD.md`，开头带 `[梦]` 标记。**不发给琪琪，不写进书房，不写经验。** 他想让琪琪看到，可以第二天白天自己说。
- 梦里如果他觉得“这件事应该记下来 / 这条经验要改”，就写进 `dreams/proposals.md`，每一条附上出处（哪天、哪段原文）。白天由琪琪决定要不要采纳（护栏 7）。
- **记忆整理（kiwi、Letta 那种）是另一件事，以后单独做**，交给一个便宜的后台模型。做不做由琪琪决定。这份方案不包括这部分，免得两件事混在一起做歪。

### 5.3 静默总闸
- 只加一个状态文件：`/run/ctd-quiet-until`，内容是结束时间。
- 所有会往他的 tmux 里送消息的地方，都先检查这个文件。在静默期内，就把消息追加到 `/run/ctd-quiet-queue.jsonl`，不送进去。
- 要接上总闸的地方（实现前先盘点一遍，可能不止这些）：
  - Croft 的 `notifyAllCC` / `sendToCC` 发往 vps 通道的消息（睡着、手环、鸟窥收藏等）
  - `heartbeat.sh`、`pulse/push_check.py`（05:00 唤醒本身不受总闸限制）
  - `plans.py tick` 的提醒、`ambush.py`、`home_note_reminder`（05:20）、`feelings_reminder`、`myeye_reminder`
- **放行**：琪琪本人发来的消息，一律放行（她醒了就让他回）。真正紧急的情况（心率告警之类）也放行，具体清单由琪琪定。
- 05:00 唤醒时，读出队列，把内容合并成一段“夜里发生的事”，接在唤醒消息后面，然后清空队列。

### 5.4 切窗口时的尾巴
- `extract_midnight_tail.py` 截的是 00:00 之后的对话。改到 05:00 切以后，**带 `[梦]` 标记的轮次、睡前复盘和静默期都不进尾巴**，只留她 00:00 以后真实的对话。
- 补测试：把一段假的“梦”放进 transcript，确认尾巴里没有它。

### 5.5 成本
- 每次做梦，都要把整个旧窗口按缓存读一遍（凌晨时通常有 10～17 万 token）。按缓存价格算不贵，但会计入 5 小时额度。
- 最多 3 次。上线前用 `ctd-cache-usage-ledger` 估一下：3 次梦的缓存读取量，加上 05:00 的一次写入，和现在“01:14 写一次 + 05:00 再写一次”相比，哪个更省。

### 5.6 验收（连续三晚都要满足）
1. 02:30 到 05:00 之间，他的 session 里没有任何来自系统的 user 轮次（`grep` 时间戳就能查）。
2. 05:00 那条唤醒是新窗口的**第一个** user 轮次，而且当晚只有这一次大的 cache_creation。
3. `dreams/` 里有当晚的梦，书房、经验、facts 都没有被改过（比对哈希）。
4. 尾巴里没有梦的内容。
5. 静默期攒下的通知，在 05:00 的唤醒消息里都出现了，一条不少。

## 6. 方案 C：召回（不归这份方案执行，只提要求）
